## Быстрый старт (Windows, PostgreSQL или MS SQL Server)

### Способ 1: Одна команда

Откройте PowerShell от имени администратора:

```powershell
irm https://raw.githubusercontent.com/air900/check-parameters-sql-server-for-1c/main/install.ps1 | iex
```

Скрипт **сам определит** установленную СУБД (PostgreSQL или MS SQL Server) и запустит соответствующую диагностику. Если команда заблокирована политикой безопасности — используйте Способ 2.

### Способ 2: Скачать и запустить

Подходит, когда политика безопасности запрещает запуск скриптов из интернета, или нужно сохранить скрипт для повторных проверок.

1. [Скачайте последний релиз](https://github.com/air900/check-parameters-sql-server-for-1c/releases) (ZIP-архив)
2. Распакуйте в любую папку
3. Откройте PowerShell от имени администратора и перейдите в каталог распакованного архива.
4. Запустите скрипт.

```powershell
.\scripts\powershell\Invoke-1CDiagnostic.ps1
```

---

### Что произойдёт после запуска

1. Скрипт определит установленную СУБД. Если доступны обе, он предложит выбрать одну.
2. Для PostgreSQL скрипт запросит пароль. Для SQL Server он использует Windows-аутентификацию по умолчанию или запросит пароль, если указан SQL-логин.
3. Если найдено несколько баз 1С, скрипт предложит выбрать базу.
4. Скрипт соберёт данные, покажет результаты и сохранит HTML-отчёт и JSON на Рабочий стол.
5. Скрипт предложит отправить данные для углублённого анализа.

### Дополнительные параметры

```powershell
# Принудительно выбрать СУБД
.\scripts\powershell\Invoke-1CDiagnostic.ps1 -DBMS postgresql
.\scripts\powershell\Invoke-1CDiagnostic.ps1 -DBMS mssql

# PostgreSQL: подключение к удалённому серверу
.\scripts\powershell\Invoke-1CDiagnostic.ps1 -DBMS postgresql -PgHost db.example.invalid -Port 5433 -Database MY_1C_DB

# MS SQL Server: именованный экземпляр + SQL-аутентификация
.\scripts\powershell\Invoke-1CDiagnostic.ps1 -DBMS mssql -MssqlHost localhost -MssqlInstance INSTANCE -SqlUsername SQL_LOGIN

# Без локальных HTML и JSON и без отправки на анализ
.\scripts\powershell\Invoke-1CDiagnostic.ps1 -NoHtml -NoPrompt
```

## Что проверяется

### PostgreSQL

| Область | Что выявляет |
|---------|-------------|
| Память и кэш | Достаточно ли памяти выделено под кэш базы данных, хватает ли памяти для сортировок и обработки запросов, корректно ли сервер оценивает доступный объём кэша |
| Журнал транзакций (WAL) | Надёжность записи данных на диск, оптимальность настроек контрольных точек, не перегружен ли диск частой записью журнала |
| Автоочистка таблиц | Включена ли автоматическая очистка (автовакуум), достаточно ли ресурсов выделено для очистки, не замедляет ли очистка работу пользователей |
| Планировщик запросов | Правильно ли сервер строит планы выполнения запросов, не использует ли медленные алгоритмы поиска там, где можно быстрее |
| Подключения | Не установлен ли слишком высокий или низкий лимит подключений, нет ли «зависших» сессий, блокирующих работу |
| Настройки для 1С | Совместимость кодировок и форматов данных с платформой 1С:Предприятие |
| Реальные метрики | Как часто данные берутся из кэша (а не с диска), сколько создаётся временных файлов, статистика контрольных точек |
| Операционная система | Настройки подкачки (swap), энергосбережение процессора, работа с большими страницами памяти, ресурсы виртуальной машины |

### MS SQL Server

| Область | Что выявляет |
|---------|-------------|
| Память сервера | Сколько памяти выделено серверу БД, не забирает ли ОС память у базы, защищён ли кэш данных от выгрузки в файл подкачки |
| Параллелизм | Как экземпляр распределяет выполнение запросов по ядрам |
| TempDB | Количество и равенство размеров файлов, авторасширение, размещение, оптимизация метаданных в памяти |
| Модель восстановления | Модель восстановления, регулярность резервного копирования журнала транзакций, автоматическое сжатие файлов |
| Статистика и индексы | Обновление статистики, контроль целостности страниц и обслуживание индексов |
| Аутентификация и права | Режим аутентификации, безопасность системной учётной записи, инициализация файлов БД |
| Trace Flags | Параллельное обновление статистики, подавление шума об успешных бэкапах в журнале ошибок |
| Конфигурация экземпляра | Порядок сортировки и сравнения строк, уровень совместимости, обработка разовых запросов |
| I/O и дисковая подсистема | Размещение файлов данных и журналов, размер блока и сжатие на уровне файловой системы |
| Регламентные операции | Заданы ли регулярные UPDATE STATISTICS / дефрагментация индексов / DBCC CHECKDB, бэкап журнала транзакций |
| ОС и оборудование | План электропитания и влияние антивируса на работу СУБД |
| Совмещение 1С + SQL | Корректно ли настроена защита памяти при совмещении на одной машине |
| Реальные метрики | Длительные транзакции (рост tempdb), цепочки блокировок, срок жизни страниц в кэше, задержки дисков, ожидания SQL Server |

## Требования

- **ОС:** Windows Server с одной из СУБД:
  - **PostgreSQL 10–17+** (любые сборки, включая `Postgres Pro`); либо
  - **MS SQL Server 2014 и новее** (Standard / Enterprise / Express). Состав метрик зависит от версии SQL Server.
- **PowerShell:** 5.1 и выше (встроен в Windows; для PS 7+ тоже работает).
- **Права для PostgreSQL:** учётные данные администратора СУБД (обычно `postgres`).
- **Права для MS SQL Server:** Windows-аутентификация (учётка с правами `VIEW SERVER STATE` и доступом к `msdb`/`master`) **либо** SQL-логин с теми же правами.
- **Безопасность:** разовая диагностика читает данные и настройки СУБД. Первичная настройка Anamnesis Kit применяется отдельно из меню.

## Как это работает

Скрипт собирает текущие значения параметров конфигурации — как есть, без интерпретации. Для углублённого анализа данные можно отправить на наш сервис, который проверит каждый параметр по рекомендациям 1С / Microsoft / экспертов сообщества и вернёт отчёт с оценкой.

Отчёт описывает обнаруженные проблемы и их влияние на работу 1С. Настройку сервера можно заказать отдельно.


## Anamnesis Kit — длительное наблюдение

Anamnesis Kit собирает снимки состояния SQL Server 2016 SP1 и новее во время работы 1С. Запустите наблюдение перед операцией, которую нужно исследовать, например перед закрытием месяца. После отправки снимков сервис вернёт ссылку на отчёт.

Запустите PowerShell от имени администратора на машине с SQL Server.

```powershell
irm https://raw.githubusercontent.com/air900/check-parameters-sql-server-for-1c/main/install-anamnesis.ps1 | iex
```

Укажите свой экземпляр SQL Server и имя базы 1С. Примените первичную настройку, запустите наблюдение, затем воспроизведите проблему в 1С. По окончании выберите «Завершить наблюдение и отправить снимки на анализ».

Требования, параметры запуска и обновление описаны в [руководстве Anamnesis Kit](scripts/anamnesis/README.md). После установки оно доступно в меню и в файле `C:\Anamnesis\README.md`.
