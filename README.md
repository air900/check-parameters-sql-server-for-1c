# Диагностика PostgreSQL и Microsoft SQL Server для 1С

За один запуск администратор 1С может проверить настройки памяти, увидеть статистику работы базы и узнать, какие сеансы блокируют друг друга. Скрипт сохраняет на рабочем столе HTML-отчёт и исходные данные в JSON. Если вы отправите снимок на бесплатный анализ, сервис покажет, какие настройки заслуживают внимания в первую очередь и почему они важны для работы 1С.

Если в 1С затягивается закрытие месяца или другая операция, Anamnesis Kit поможет разобраться, что происходило в SQL Server именно в это время. Серия снимков покажет, какие запросы выполнялись и каких ресурсов они ждали.

## Быстрый старт

На Windows-сервере, где работает СУБД, откройте Windows PowerShell 5.1 от имени администратора и выполните команду.

```powershell
irm https://raw.githubusercontent.com/air900/check-parameters-sql-server-for-1c/main/install.ps1 | iex
```

Для запуска из файла скачайте ZIP-архив диагностики (`1c-diagnostic-v*.zip`). Распакуйте его, перейдите в каталог с распакованными файлами и выполните команду в PowerShell. [Скачать последний релиз](https://github.com/air900/check-parameters-sql-server-for-1c/releases/latest)

```powershell
.\scripts\powershell\Invoke-1CDiagnostic.ps1
```

Скрипт найдёт установленную СУБД и базы 1С. Если он предложит выбор, укажите нужную СУБД и базу. Для PostgreSQL введите пароль. К SQL Server скрипт по умолчанию подключается под текущей учётной записью Windows.

### Параметры запуска

```powershell
# PostgreSQL: указать порт и базу
.\scripts\powershell\Invoke-1CDiagnostic.ps1 -DBMS postgresql -Port 5433 -Database MY_1C_DB

# Именованный экземпляр SQL Server и SQL-аутентификация
.\scripts\powershell\Invoke-1CDiagnostic.ps1 -DBMS mssql -MssqlHost localhost -MssqlInstance INSTANCE -SqlUsername SQL_LOGIN

# Сохранить HTML и JSON локально без отправки на анализ
.\scripts\powershell\Invoke-1CDiagnostic.ps1 -NoPrompt
```

Если нужен только вывод в консоль, используйте `-NoHtml -NoPrompt`.

## Требования

| СУБД на Windows Server | Что потребуется для разовой диагностики |
|---|---|
| PostgreSQL 14 и новее | Клиент `psql` и учётная запись с доступом к базе `postgres`, выбранной базе 1С и статистике сервера. По умолчанию скрипт использует учётную запись `postgres`. |
| SQL Server 2014 и новее | Учётная запись Windows или SQL-логин с доступом к выбранной базе, системным базам `master` и `msdb`, а также к диагностическим представлениям сервера. Набор показателей зависит от версии, редакции и прав учётной записи. |

## Состав снимка и отправка на анализ

Разовая диагностика работает в режиме чтения.

- **PostgreSQL.** Настройки памяти, журнала предзаписи (WAL), автовакуума и планировщика запросов. Статистика использования кэша и временных файлов, сведения о блокировках.
- **SQL Server.** Настройки памяти, параллелизма и `tempdb`, модель восстановления и сведения об обслуживании баз. Статистика ожиданий, блокировки и задержки чтения и записи.
- **Windows.** Сведения о процессорах, памяти, дисках и плане электропитания.

Перед отправкой вы можете открыть JSON и посмотреть, какие данные собрал скрипт. В файле могут быть имя сервера, названия баз, имена пользователей и адреса клиентских подключений. При блокировках в PostgreSQL в снимок могут попасть фрагменты SQL-запросов, в том числе из других баз того же экземпляра.

Скрипт ждёт вашего ответа в консоли. При ответе «Нет» или `N` данные остаются на сервере, где вы запустили проверку. После «Да» или `Y` скрипт передаёт снимок по HTTPS. Сервис сохраняет его и возвращает ссылку на HTML-отчёт. При оценке настроек он учитывает документацию Microsoft, материалы специалистов по SQL Server и [рекомендации 1С](https://its.1c.ru/db/metod8dev#browse:13:-1:3199:3258).

## Наблюдение во время операции 1С

Anamnesis Kit работает с SQL Server 2016 SP1 и новее. По умолчанию он делает один снимок в минуту. Для установки выполните команду в Windows PowerShell от имени администратора на сервере SQL Server.

```powershell
irm https://raw.githubusercontent.com/air900/check-parameters-sql-server-for-1c/main/install-anamnesis.ps1 | iex
```

1. Укажите экземпляр SQL Server и базу 1С. Если меню запросит первичную настройку, используйте учётную запись с ролью `sysadmin`. Комплект включает Query Store в выбранной базе, настраивает регистрацию длительных блокировок и запускает сеанс Extended Events на экземпляре. Начиная с SQL Server 2017 комплект также пытается включить автоматическую коррекцию планов.
2. Выберите «Начать наблюдение». Дождитесь первого снимка, затем запустите операцию в 1С. Для анализа нужны хотя бы два снимка.
3. После завершения операции проверьте снимки в каталоге `data\snapshots`. В них могут быть тексты запросов и планы выполнения из выбранной базы и из других баз того же экземпляра.
4. Чтобы получить отчёт для специалиста, выберите «Завершить наблюдение и отправить снимки на анализ». В архив войдут снимки и сведения о сеансе наблюдения. Файлы Extended Events останутся на сервере. По ссылке откроются краткие выводы, технические данные и рекомендации по проверке. [Требования и руководство Anamnesis Kit](scripts/anamnesis/README.md)
