# Anamnesis Kit

Anamnesis Kit записывает, что происходит в SQL Server, пока 1С проводит документы или выполняет расчёт. После отправки снимков специалист получает отчёт о запросах и ожиданиях с пояснениями и командами для проверки.

## Быстрый старт

1. Откройте PowerShell от имени администратора на Windows-сервере с SQL Server и запустите установку.

   ```powershell
   irm https://raw.githubusercontent.com/air900/check-parameters-sql-server-for-1c/main/install-anamnesis.ps1 | iex
   ```

2. В меню укажите экземпляр, например `localhost` или `localhost\INSTANCE`, и имя базы 1С. Примените первичную настройку SQL Server, если меню показывает, что она требуется.
3. Выберите «Начать наблюдение». Дождитесь первого снимка в окне состояния сбора, затем запустите операцию в 1С.
4. После завершения операции выберите «Завершить наблюдение и отправить снимки на анализ». Когда сервис примет архив, меню покажет ссылку на технический отчёт.

## Требования

- Windows Server с SQL Server 2016 SP1 или новее и Windows PowerShell 5.1.
- `sqlcmd.exe`, `tar.exe` и `curl.exe` в `PATH`.
- Запуск на машине SQL Server под учётной записью Windows с правом запуска заданий планировщика и чтения диагностических данных SQL Server.
- Для первичной настройки нужна учётная запись с ролью sysadmin. Комплект включает Query Store в выбранной базе, настраивает регистрацию длительных блокировок на экземпляре и запускает сеанс Extended Events. На SQL Server 2017 и новее он также пытается включить автоматическую коррекцию планов. Службе SQL Server требуется право записи в каталог `data\xe` внутри папки комплекта.
- Доступ по HTTPS к GitHub для установки и к сервису для отправки архива.

## Сбор данных и отправка

По умолчанию планировщик снимает состояние SQL Server раз в минуту в течение восьми часов. Продолжительность выбирают при запуске. При закрытии окна состояния сбор продолжится по расписанию. Для анализа нужны как минимум два снимка.

Снимки хранятся в `data\snapshots`. Они могут содержать тексты SQL-запросов и планы выполнения из выбранной и других баз на том же экземпляре SQL Server. Сервис анализа audit-reshenie.ru получает эти снимки, сведения о сеансе и email, если его указали. Файлы Extended Events хранятся локально в `data\xe`. Проверьте, что передача снимков согласована с правилами вашей организации.

## Повторный запуск и обновление

Открыть меню после установки можно из PowerShell от имени администратора.

```powershell
& 'C:\Anamnesis\Run-Anamnesis.ps1'
```

При новом наблюдении комплект сохраняет предыдущие снимки в соседнем каталоге `data\snapshots-…` и начинает сбор в пустом каталоге. Меню отправляет только снимки для выбранного экземпляра SQL Server и базы. Чтобы отправить предыдущий набор, запустите `upload\Upload-Archive.ps1` с параметром `-SnapshotDir` и укажите его каталог.

Перед обновлением завершите наблюдение в прежнем комплекте. Остановите его сессию Extended Events в SQL Server Management Studio. Запустите обновление с учётной записью Windows, которая входит в роль sysadmin на экземпляре SQL Server. Установщик запросит имя экземпляра, использованного предыдущей установкой. Если сохранилась задача наблюдения или активная сессия Extended Events, установщик укажет её имя. Снимки, трассы и архивы сохраняются.
